# Read aloud

Open **Accessibility** using the accessibility icon in the global header, then set **Narrator → ON**. Narrator defaults to **OFF**. The shared root controller is the single source of truth; `iqlrs.accessibility.narrator` in local storage persists explicit consent across navigation and reloads and synchronizes changes between tabs. Blocked storage falls back to a session preference. Enabling never starts playback. Disabling immediately cancels requests and playback, clears highlighting, and removes all narration controls and narration-only layout wrappers.

All eight lessons use their existing content catalogue for narration. Reusable Listen controls also cover the landing page's educational explanations, introductions, quizzes and revealed feedback, State Explorer, circuit instructions and challenges, simulation interpretation, and Code Lab explanations. Navigation and unrevealed answers are excluded.

Set `OPENAI_API_KEY` in the backend environment, using `.env.example` for the remaining settings, to enable neural narration. Restart the backend. The default is OpenAI `gpt-4o-mini-tts` with `marin`, natural instructor delivery instructions, and an explicit AI voice disclosure. Secrets stay on the backend.

If the speech service is unconfigured, unreachable, fails, or takes longer than 15 seconds to respond, the same controller uses browser SpeechSynthesis with the same normalized content. The player identifies this as “Browser voice”. This transport requires a working English speech voice on the device; unsupported browsers or unavailable voices show an actionable error. Browser gesture restrictions can require pressing Retry audio. Each utterance is bounded to 240 characters, retained until completion, and cancelled with its handlers detached before replacement. Voices are re-queried for each utterance, accommodating asynchronous voice availability. Browser playback provides pause/resume, stop, replay, and segment navigation; it omits the unsupported audio seek timeline. Speed and volume changes apply to subsequent spoken sentences. See [SpeechSynthesis lifecycle methods](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis).

The original failure in this checkout was an unconfigured neural provider (`OPENAI_API_KEY` absent) with no fallback. Listen controls were always rendered because no accessibility preference existed. Repeated Listen clicks restarted the request instead of stopping it, and a failed request remained marked pending, allowing Resume to get stuck loading. The shared controller now enforces the preference, releases completed/failed requests, falls back to browser speech, and guards late callbacks after stop or replacement.

Provider selection lives in `backend/app/services/speech/provider.py`; another provider implements its small protocol and factory entry. Model, voice, delivery instructions and text determine cache identity. See the [OpenAI speech guide](https://developers.openai.com/api/docs/guides/text-to-speech).

Text normalization handles lists, headings, Greek symbols, quantum states, tensor products and common technical names without changing displayed content. Fenced code is identified rather than read character by character. Sentence-based chunks are generated lazily (900 characters; server limit 1600). Short MP3 chunks enable seeking and prompt cancellation; playback pauses briefly at uncached chunk boundaries rather than downloading a whole lesson first.

One shared controller owns playback. An active Listen button becomes Stop narration (Cancel loading while preparing). Pause/resume, stop, replay, segment navigation, seeking, speed and volume are keyboard accessible. The current section is highlighted; scrolling is explicit. Navigation, content changes, unmounts, disabling Narrator, and leaving the page cancel generation and release object URLs or browser utterances. Ordinary rerenders preserve playback.

The browser caches up to 24 MiB for 30 minutes. SQLite provides persistent bounded audio caching and an atomic daily character budget across workers. Request rate, concurrent generation and pending work are bounded per worker; duplicate generation is coalesced within a worker. Multiple workers can still generate the same first uncached chunk concurrently. Configure deployment-wide limits at the gateway when scaling. Failed or cancelled generation can consume reserved character budget conservatively. Keep the configured cache volume writable and persistent.

Run `npm run typecheck`, `npm run lint`, `npm test`, and `npm run build` in `frontend`; run `backend/.venv/bin/python -m pytest backend/tests -q` from the repository root. Tests cover normalization, long lessons, controller transitions, cancellation, cache reuse, API validation, safe errors and budgets. A real provider key is required to validate actual neural voice quality; synthetic audio fixtures only validate player behavior.

Continuation verification: 22 backend tests and 10 frontend unit cases passed, along with typecheck, lint and production build. Headless Chrome passed 72 route/viewport combinations without document overflow or runtime exceptions. All eight lessons were checked with an audio fixture at 1440, 768, 375 and 320 pixels for explicit playback, pause/resume, replay/cache reuse, speed, highlighting, segment navigation and stop. Additional browser checks passed failure/retry, navigation cleanup, mouse and touch gate movement, keyboard gate movement, and simulation execution indicators. Actual provider audio remains unverified without an API key.

Narrator accessibility refinement verification: 12 narration unit cases pass, including OFF gating, late request cancellation, browser fallback ownership, delayed voices, pause during loading, and retry after failure. Chrome checks cover 18 routes at 1440, 1024, 375, and 320 pixels with Narrator OFF (no narration controls, wrappers, requests, overflow, or header overlap), plus ON layouts, keyboard toggling, reload/navigation persistence, cross-tab disabling, start/stop, rapid clicks, pause/resume, and replacement. Real HTMLAudio playback was verified with a generated WAV fixture, including cache reuse and route cleanup. Browser SpeechSynthesis was stubbed for deterministic lifecycle checks; unavailable speech and blocked local storage were also checked. Actual neural voice quality and device voice output require a configured provider or installed speech voice and a listening check.
